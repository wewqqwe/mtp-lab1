# Частотный анализ текста

**Осетрова Алина Романовна, группа 221141, вариант 3, лабораторная №1**

Учебный проект для лабораторной работы №1 по дисциплине
«Методы и технологии программирования» (часть 1).
Программа читает текстовый файл и показывает сводку по нему:
размер, долю уникальных слов и самые частые слова.

## Задания варианта 3

| Сложность | № | Задание |
|---|---|---|
| Средняя | 3 | Добавить файл, сделать коммит |
| Средняя | 5 | Создать ветку `feature`, добавить новый файл |
| Средняя | 9 | Отправить изменения на GitHub |
| Повышенная | 3 | Создать Pull Request |
| Повышенная | 7 | Создать релиз (tag) на GitHub |

## Структура проекта

```
.gitignore        правила игнорирования для Python
main.py           точка входа, разбор аргументов и вывод
text_loader.py    чтение текста из файла
frequency.py      частотный анализ слов
report.py         оформление результата таблицей
data/sample.txt   образец текста
```

Модули разделены по ответственности: чтение файла, подсчёт частот и
оформление отчёта не зависят друг от друга, поэтому каждый из них можно
менять и проверять отдельно.

## Запуск

```
python main.py                       # образец из data/sample.txt
python main.py data/sample.txt 6     # свой файл и число слов
```

Вывод программы:

```
Файл: data/sample.txt
Символов: 290
Строк: 5
Непустых строк: 5
Доля уникальных слов: 0.9231
Самые частые слова:
  проекта        3
  версии         2
  git            1
  вернуться      1
  версий         1
```

После слияния ветки `feature/report-table` результат выводится таблицей:

## Задание средней сложности №3: добавить файл, сделать коммит

Каждый файл добавлен отдельным коммитом, сообщения — в формате
Conventional Commits:

```
chore: добавить .gitignore для Python-проекта
feat: добавить чтение текста из файла
feat: выводить сводку по текстовому файлу
```

## Задание средней сложности №5: ветка feature и новый файл

Создана ветка `feature/word-frequency`, в ней появился новый файл
`frequency.py` с частотным анализом, затем ветка слита в `main`
слиянием **без ускоренной перемотки**, чтобы в истории остался
merge-коммит:

```
git checkout -b feature/word-frequency
git add frequency.py
git commit -m "feat: добавить частотный анализ слов"
git checkout main
git merge --no-ff feature/word-frequency -m "merge: влить feature/word-frequency в main"
```

Доказательство — merge-коммит с двумя родителями:

```
4b866ce merge: влить feature/word-frequency в main

Родители: 2fb6a2b 3eadc19
```

## Задание повышенной сложности №3: Pull Request

Работа над табличным отчётом велась в отдельной ветке
`feature/report-table`. Ветка отправлена на GitHub, изменения влиты
в `main` через Pull Request — так изменения проходят обзор до попадания
в основную ветку, а обсуждение остаётся в истории проекта.

* Pull Request: https://github.com/wewqqwe/mtp-lab1/pull/1
* Ветка: `feature/report-table`
* Способ слияния: merge commit (без перемотки, слияние видно в истории)

```
git push -u origin feature/report-table
gh pr create --base main --head feature/report-table \
    --title "Табличный отчёт по частотам слов" \
    --body "Выносит оформление результата в отдельный модуль report.py"
gh pr merge 1 --merge
```

## Задание повышенной сложности №7: релиз (tag) на GitHub

На слитое состояние `main` поставлена **аннотированная** метка `v1.0.0`
(аннотированная, а не лёгкая: она хранит автора, дату и описание, и
именно такие метки предназначены для релизов):

```
git tag -a v1.0.0 -m "Первая версия: сводка, частоты слов и таблица"
git push origin v1.0.0
gh release create v1.0.0 --title "v1.0.0" --notes "..."
```

* Релиз: https://github.com/wewqqwe/mtp-lab1/releases/tag/v1.0.0
